Week 4 — Preparing Economic Data for Analysis

Week 4 — Preparing Economic Data for Analysis

Weeks 1-3 built the foundation:

  • running Python code
  • importing and inspecting data
  • using logic, loops, and functions
  • checking whether code matches an economic rule

Week 4 is the next step.

The focus is no longer:

Can I run a Python command?

The focus is:

Can I turn raw economic data into analysis-ready data?

This matters because most analytical mistakes happen before modelling begins. If the data are poorly prepared, the graphs, dashboards, forecasts, and machine learning models will also be unreliable.

1. Learning Outcomes

By the end of this week, students should be able to:

  • explain the difference between raw data and analysis-ready data
  • inspect a dataset for structure, data types, missing values, and suspicious values
  • clean column names and standardize variable formats
  • create economically meaningful variables
  • recode numerical values into interpretable categories
  • document data-cleaning decisions
  • produce a clean dataset that can be used in Weeks 5 and 6

4. Why Week 4 Is Not a Repeat of Week 2

Week 2 introduced how to open and inspect data.

Week 4 asks a more professional question:

Is this dataset reliable enough to support an economic conclusion?

That requires judgment.

For example, after importing data, an analyst should ask:

  • Are the variables named consistently?
  • Are numerical variables stored as numbers?
  • Are there missing values?
  • Are values economically plausible?
  • Are classifications coded clearly?
  • Can another person understand how the dataset was prepared?

This is the difference between basic coding and analytical practice.

5. Raw Data vs Analysis-Ready Data

Raw data are data as initially collected, downloaded, or received.

Analysis-ready data are data that have been checked, cleaned, documented, and structured for a specific analytical purpose.

Raw Data Problem Why It Matters
Missing values Can distort averages and comparisons
Incorrect data types Prevent calculations
Inconsistent names Create coding errors
Extreme values May indicate crisis, error, or special events
Undocumented categories Make interpretation unclear

Economists should not clean data mechanically. Every cleaning decision should be linked to the purpose of the analysis.

6. Import and Audit the Dataset

import pandas as pd

data = pd.read_csv(url)

data.head()

Start with a simple audit:

data.shape
data.columns
data.info()
data.describe()

Interpretation questions:

  1. What is one row in this dataset?
  2. What is one column in this dataset?
  3. Which variables can be used for numerical analysis?
  4. Which variables need checking before analysis?

7. Data Types and Economic Meaning

Python only sees objects, numbers, and labels.

Economists must connect those technical types to economic meaning.

Variable Technical Type Economic Meaning
Year integer Time period
Inflation float Price instability
GDP_Growth float Economic expansion or contraction
Exchange_Rate float/integer Value of domestic currency against foreign currency
Reserves float/integer External buffer
Unemployment float Labour market condition

The same command may be technically correct but economically meaningless if the variable is misunderstood.

8. Missing Values

Missing values are not just technical problems. They are economic information problems.

data.isna().sum()

If missing values exist, students should ask:

  • Is the value truly unavailable?
  • Was it not collected?
  • Is the missing value concentrated in a specific period?
  • Would dropping the row remove an important crisis year?

Common approaches:

Approach When It May Be Reasonable
Keep missing value When absence itself should be visible
Drop observation When few rows are affected and no bias is created
Fill using a rule When the rule is defensible and documented

Never hide a missing-value decision.

9. Suspicious Values and Outliers

Extreme values may be errors, but they may also be economically important.

data.sort_values("Inflation", ascending=False)
data.sort_values("GDP_Growth")

Example:

High inflation may be a crisis signal, not a data error.

Before removing or changing an outlier, ask:

  • Is the value impossible?
  • Is the value unusual but historically plausible?
  • Does the value represent the event we are trying to study?

For economic analysis, deleting crisis years usually destroys the story.

10. Cleaning Column Names

Clean names reduce errors.

data.columns = (
    data.columns
    .str.strip()
    .str.replace(" ", "_")
)

Good variable names should be:

  • short
  • readable
  • consistent
  • easy to type
  • connected to meaning

11. Creating New Economic Indicators

Raw variables often need to be transformed into useful indicators.

Exchange Rate Change

data["Exchange_Rate_Change"] = data["Exchange_Rate"].pct_change() * 100

This creates a year-to-year percentage change.

Interpretation:

A positive value means the exchange rate increased compared with the previous year.

In many contexts, this may indicate currency depreciation.

Reserve Adequacy Signal

data["Low_Reserves"] = data["Reserves"] < 4000

This creates a simple warning indicator.

Recession Indicator

data["Recession"] = data["GDP_Growth"] < 0

This converts an economic rule into a variable.

12. Recoding Into Categories

Categories help communicate economic conditions.

def classify_inflation(rate):
    if rate < 5:
        return "Low"
    elif rate <= 15:
        return "Moderate"
    else:
        return "High"

data["Inflation_Category"] = data["Inflation"].apply(classify_inflation)

This builds directly on Week 3.

Week 3 asked:

Can we write the rule?

Week 4 asks:

Can we apply the rule correctly to a dataset?

13. Quality Checklist

Before using the dataset in Week 5, check:

data.info()
data.isna().sum()
data.describe()
data.head()

Then answer:

  1. Are all required variables present?
  2. Are numerical variables stored as numbers?
  3. Are missing values understood?
  4. Are new variables correctly created?
  5. Are classifications consistent with the economic rule?
  6. Can another student understand your cleaning decisions?

14. Documentation

A clean dataset is not enough. Students must document what they changed.

Example:

I created Exchange_Rate_Change using percentage change in Exchange_Rate.
The first year is missing because there is no previous year for comparison.
I classified inflation as Low below 5, Moderate from 5 to 15, and High above 15.
I did not remove 2022 because it represents an important crisis observation.

This kind of explanation turns code into analysis.

15. Week 4 Output

By the end of Week 4, students should have:

  • a cleaned macroeconomic dataset
  • at least three new analytical variables
  • one classification variable based on an economic rule
  • a short data-quality note
  • a notebook that can be reused in Weeks 5 and 6

16. Summary

Week 4 is the bridge from basic Python to real analytics.

The core lesson is:

Good analysis begins with careful data preparation.

In Week 5, students will use the prepared dataset to produce descriptive statistics, graphs, and evidence-based interpretations.
