Week 4 — Preparing Economic Data for Analysis

Week 4 — Preparing Economic Data for Analysis

Weeks 1-3 gave students the foundation:

  • running Python code
  • understanding variables and data types
  • importing and inspecting data
  • using conditions, loops, and functions
  • checking whether code follows an economic rule

Week 4 is where those skills become a real analytical workflow.

The central question is:

Can I turn raw economic data into analysis-ready data?

This is one of the most important skills in industrial data analytics. A model, graph, dashboard, or AI-generated result is only as reliable as the data behind it.

1. Learning Outcomes

By the end of this week, students should be able to:

  • explain the difference between raw data and analysis-ready data
  • conduct a structured data audit
  • check rows, columns, data types, missing values, duplicates, and suspicious values
  • connect technical data checks to economic meaning
  • clean column names and standardize variables
  • create economically meaningful indicators
  • classify observations using economic rules
  • test boundary values in classification rules
  • prepare a clean dataset for Week 5 exploratory analysis
  • document data-preparation decisions clearly

4. Why Week 4 Matters

In real economic analysis, the data rarely arrive ready for use.

Common problems include:

  • inconsistent variable names
  • numbers stored as text
  • missing observations
  • duplicated rows
  • extreme values
  • unclear category labels
  • variables that need to be constructed from raw columns

If these problems are ignored, the analysis becomes unreliable.

Example:

If inflation is stored as text, Python may not calculate the average correctly.
If a crisis year is removed as an "outlier", the analysis may erase the most important event.
If missing data are dropped without explanation, the result may become biased.

Therefore, Week 4 is about professional discipline.

6. Raw Data vs Analysis-Ready Data

Raw data are data as received.

Analysis-ready data are data that have been:

  • inspected
  • cleaned
  • checked
  • documented
  • structured for a specific analytical question
Raw Data Problem Technical Issue Economic Risk
Missing values NaN values appear Averages and comparisons may be misleading
Wrong data type Number stored as text Calculations may fail
Duplicate rows Same observation repeated Results may be double counted
Extreme values Very high or low values Could be error or important crisis signal
Unclear categories Poor labels Interpretation becomes weak

Key point:

Data cleaning is not just technical. It is analytical.

7. The Data Audit Framework

A good data audit asks five questions:

  1. What is the unit of observation?
  2. What variables are available?
  3. Are the data types correct?
  4. Are there missing, duplicated, or suspicious values?
  5. What new variables are needed for analysis?

In pandas:

data.head()
data.shape
data.columns
data.info()
data.describe()
data.isna().sum()
data.duplicated().sum()

Students should not simply run these commands. They should explain what each command reveals.

9. Understanding the Unit of Observation

Before analysis, identify the unit of observation.

In this dataset:

Each row represents one year.

This matters because interpretation depends on the unit.

If one row is a person, we analyze individual differences.

If one row is a year, we analyze changes over time.

If one row is a district, we analyze spatial differences.

Check:

data.shape

Interpretation:

The dataset has a small number of annual observations, so the analysis should be descriptive and cautious.

10. Inspecting Data Types

data.info()

This shows:

  • column names
  • number of non-missing observations
  • data types
  • memory usage

Important data types:

pandas Type Meaning
int64 Whole number
float64 Decimal number
object Text or mixed type
bool True or False

Economic interpretation:

Inflation, GDP growth, reserves, unemployment, and exchange rates should be numerical because we need to calculate changes, averages, and comparisons.

11. Summary Statistics Are Data Checks

data.describe()

This is not yet final analysis.

In Week 4, describe() is used as a quality check.

Ask:

  • Are the minimum and maximum values plausible?
  • Does any value look impossible?
  • Are there extreme values that need explanation?
  • Are units clear?

Example:

Very high inflation may not be an error. It may represent a crisis year.

12. Missing Values

Missing values are not just a coding issue.

They raise economic questions:

  • Was the statistic not collected?
  • Was the value unavailable?
  • Is the missing value concentrated in crisis years?
  • Would removing the row change the story?

Check:

data.isna().sum()

Common decisions:

Decision When It May Be Suitable
Keep missing value When absence should remain visible
Drop row When missingness is limited and not central
Fill value When there is a defensible rule
Investigate source When the missing value affects the conclusion

Professional rule:

Do not hide missing-value decisions. Document them.

13. Duplicates

Duplicate rows can distort results.

data.duplicated().sum()

If duplicates exist:

data = data.drop_duplicates()

But do not drop duplicates blindly.

Ask:

  • Are the rows truly duplicated?
  • Is there a reason the same year appears twice?
  • Does the duplicate represent a different source, region, or revision?

14. Suspicious Values and Outliers

Outliers are observations that are very different from the rest.

They may be:

  • data entry errors
  • measurement problems
  • genuine economic shocks
  • crisis observations

Find extreme values:

data.sort_values("Inflation", ascending=False)
data.sort_values("GDP_Growth")
data.sort_values("Reserves")

Important distinction:

Unusual does not mean wrong.

For this course, crisis years should usually be kept, because they are central to economic interpretation.

15. Class Discussion: Should We Remove 2022?

Suppose 2022 has very high inflation and negative GDP growth.

Discuss:

  1. Is this value impossible?
  2. Is this value historically meaningful?
  3. What happens if we remove it?
  4. Would removing it make the data cleaner or less truthful?

Expected conclusion:

The value should normally be kept because it represents an important macroeconomic event.

This is why economists must think before cleaning.

16. Cleaning Column Names

Messy names create coding errors.

Good column names are:

  • short
  • readable
  • consistent
  • easy to type
  • meaningful

Standardize names:

data.columns = (
    data.columns
    .str.strip()
    .str.replace(" ", "_")
)

Check:

data.columns

This pattern is useful because real datasets often contain spaces, hidden characters, and inconsistent naming.

17. Creating Analytical Variables

Raw variables are often not enough.

Economists create new variables to represent analytical concepts.

Examples:

Analytical Concept Variable
Currency pressure Exchange rate percentage change
Economic contraction Recession indicator
External vulnerability Low reserve indicator
Price instability Inflation category

This is where Week 3 logic becomes Week 4 data preparation.

18. Exchange Rate Percentage Change

The exchange rate level is useful, but the change is often more informative.

data["Exchange_Rate_Change"] = data["Exchange_Rate"].pct_change() * 100

Interpretation:

The first year will be missing because there is no previous year for comparison.

Ask students:

  1. Why does the first year become missing?
  2. Should we fill it with zero?
  3. What would zero incorrectly imply?

Recommended interpretation:

Do not automatically fill the first value with zero. It is missing because the calculation requires a previous year.

19. Recession Indicator

An economic rule can become a variable.

Rule:

Negative GDP growth indicates contraction.

Code:

data["Recession"] = data["GDP_Growth"] < 0

This creates a Boolean variable:

True or False

Use it to identify recession years:

data[data["Recession"]]

20. Low Reserves Indicator

A simple warning indicator can be created using a threshold.

data["Low_Reserves"] = data["Reserves"] < 4000

Important:

The threshold is a teaching rule for this exercise, not a universal policy rule.

Students should understand that thresholds must be justified.

Ask:

  • Who decides the threshold?
  • Would another threshold change the conclusion?
  • Should the threshold be based on theory, policy, or data?

21. Inflation Classification

Use Week 3 conditional logic to classify inflation.

def classify_inflation(rate):
    if rate < 5:
        return "Low"
    elif rate <= 15:
        return "Moderate"
    else:
        return "High"

data["Inflation_Category"] = data["Inflation"].apply(classify_inflation)

The rule is:

Inflation Rate Category
Below 5 Low
5 to 15 Moderate
Above 15 High

22. Boundary Testing

Always test boundary values.

test_values = [4.9, 5, 15, 15.1]

for value in test_values:
    print(value, "->", classify_inflation(value))

Ask:

  1. What happens at 5?
  2. What happens at 15?
  3. What happens just below and just above the threshold?

This protects students from flawed AI-generated code such as:

def classify_inflation(inflation):
    if inflation < 15:
        return "Low"
    elif inflation < 5:
        return "Moderate"
    else:
        return "High"

Problem:

The second condition can never be reached.

23. Filtering the Prepared Dataset

After creating indicators, students can filter meaningful periods.

High inflation years:

data[data["Inflation_Category"] == "High"]

Recession years:

data[data["Recession"]]

Years with low reserves:

data[data["Low_Reserves"]]

Combined conditions:

data[
    (data["Inflation_Category"] == "High") &
    (data["Recession"])
]

Interpretation:

Combined filters help identify periods of multiple macroeconomic stress.

25. Data Documentation

A prepared dataset must be documented.

Students should write a short note explaining:

  • what the dataset contains
  • what each new variable means
  • how missing values were handled
  • why extreme values were kept
  • what limitations remain

Example:

I created Exchange_Rate_Change using percentage change in Exchange_Rate. The first year is missing because there is no previous year for comparison. I classified inflation as Low below 5, Moderate from 5 to 15, and High above 15. I kept 2022 because it represents an important crisis observation rather than a data error.

This note makes the analysis transparent.

28. Common Student Mistakes

Mistake Why It Is a Problem
Running code without interpreting output Produces technical work without analysis
Dropping missing values automatically May remove important observations
Removing crisis years as outliers Can erase the main economic story
Creating variables without explaining them Makes results hard to understand
Using thresholds without testing boundaries Can create incorrect classifications
Trusting AI-generated code without checking logic May produce silent errors

29. Responsible AI Use in Week 4

Students may use AI tools to help understand syntax, but they must verify the result.

Good AI prompt:

I have a pandas DataFrame with Inflation, GDP_Growth, Exchange_Rate, and Reserves. Help me create a recession indicator and explain how to test whether the logic is correct.

Weak AI prompt:

Clean my data.

Students must be able to explain:

  • what the code does
  • why the variable is created
  • whether the output matches the economic rule
  • what limitations remain

Data preparation is analytical reasoning, not clerical cleaning.
