Week 13 — Capstone Integration: From Data to Economic Intelligence

Week 13 — Building End-to-End Economic Analytics Projects and AI-Powered Decision Systems

Weeks 1–12 introduced:

  • Python fundamentals
  • data handling
  • visualization
  • regression
  • machine learning
  • forecasting
  • NLP
  • generative AI

This final week integrates everything into:

complete analytical systems

Students now move from:

learning individual tools

to:

designing full analytical workflows

This week focuses on:

  • project integration
  • analytical pipelines
  • economic storytelling
  • dashboard communication
  • AI-assisted workflows
  • reproducibility
  • ethical reasoning
  • critical interpretation

Critical Conceptual Goal

Students must understand:

analytics is not coding alone

Good economic analytics requires:

  • theory
  • judgment
  • communication
  • skepticism
  • interpretation
  • reproducibility
  • ethics

The final goal of the course is NOT:

students who can run code

The goal is:

students who can think computationally about economic problems

1. Learning Objectives

By the end of this week, students should be able to:

  • explain what an end-to-end analytics workflow is
  • formulate meaningful economic questions
  • design analytical pipelines
  • clean and validate datasets
  • perform exploratory analysis
  • choose appropriate models
  • evaluate predictions and forecasts
  • communicate results effectively
  • explain reproducibility principles
  • critically evaluate AI-assisted workflows
  • discuss ethical implications of analytics systems

3. What Is an End-to-End Analytics Project?

Real-world analytics projects involve:

  • multiple stages
  • multiple tools
  • multiple decisions

Example Workflow

A policy analytics project may involve:

  • collecting data
  • cleaning data
  • visualizing patterns
  • estimating models
  • forecasting outcomes
  • building dashboards
  • communicating findings

Important Lesson

Professional analytics is:

  • iterative
  • messy
  • uncertain

Not:

run one model and finish

4. The Economic Analytics Pipeline

Modern analytics usually follows a pipeline.

Typical Pipeline

Problem → Data → Cleaning → Exploration → Modeling → Evaluation → Communication → Policy Insight

Important Lesson

Weakness at any stage weakens the entire analysis.

Example

A sophisticated ML model cannot rescue:

  • poor data
  • poor theory
  • poor interpretation

Critical Lesson

Analytics quality depends more on:

thinking

than:

software complexity

5. Problem Formulation

Bad questions produce bad analysis.

Weak Question

Use AI on economic data.

Better Question

Can macroeconomic indicators help forecast inflation instability in Sri Lanka?

Important Lesson

Good analytical questions are:

  • specific
  • measurable
  • meaningful
  • theoretically grounded

Critical Lesson

Coding cannot compensate for:

vague thinking

6. Data Collection and Cleaning

Most real-world projects spend enormous effort on:

  • data collection
  • cleaning
  • preprocessing

Important Tasks

  • handling missing values
  • merging datasets
  • validating consistency
  • preprocessing text
  • formatting variables

Example

data.isnull().sum()

Critical Lesson

Poor data quality produces:

  • misleading conclusions
  • unstable models
  • unreliable forecasts

Important Reminder

Always inspect data critically.

7. Exploratory Data Analysis

Before modeling:

understand the data

Important Questions

Ask:

  • What patterns exist?
  • Are there outliers?
  • Are relationships plausible?
  • Are variables stable?

Example Visualization

plt.scatter(data["Inflation"],
            data["Exchange_Rate"])

plt.show()

Critical Lesson

Many modeling errors could be avoided through better exploration.

future reliability

11. AI-Assisted Workflows

Modern analysts increasingly use:

  • generative AI
  • coding assistants

Examples

AI systems can help:

  • write code
  • summarize reports

12. Reproducibility and Documentation

Professional analytics must be reproducible.

Reproducibility Means

Another analyst should be able to:

  • rerun the analysis
  • understand the workflow
  • verify the results

Important Practices

  • clear file organization
  • comments in code
  • documented assumptions
  • reproducible notebooks

Example

# Load inflation dataset
data = pd.read_csv("inflation.csv")

Critical Lesson

Undocumented analysis is:

  • difficult to trust
  • difficult to audit
  • difficult to reproduce

20. Live Coding Session

Activity Title

Building an Integrated Economic Analytics Workflow

Step 1 — Import Libraries

import pandas as pd
import matplotlib.pyplot as plt

from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error

Step 2 — Load Dataset

data = pd.read_csv("macro_project_data.csv")

Step 3 — Clean Data

data.dropna(inplace=True)

Step 4 — Visualize Relationships

plt.scatter(data["Exchange_Rate"],
            data["Inflation"])

plt.show()

Step 5 — Train Model

X = data[["Exchange_Rate"]]

y = data["Inflation"]

model = LinearRegression()

model.fit(X, y)

Step 6 — Generate Predictions

predictions = model.predict(X)

Step 7 — Evaluate Performance

mean_absolute_error(y,
                    predictions)

Step 8 — Visualize Predictions

plt.plot(y,
         label="Actual")

plt.plot(predictions,
         label="Predicted")

plt.legend()

plt.show()

Step 9 — Interpretation Questions

Ask:

  • What assumptions exist?
  • What limitations emerge?
  • Would policymakers trust this model?
  • Could the model fail during crises?

24. Common Errors

Problem 1 — Overcomplicated Models

Complexity does not guarantee insight.

Problem 2 — Weak Problem Formulation

Poor questions produce poor analysis.

Problem 3 — Ignoring Uncertainty

All models contain limitations.

Problem 4 — Blind Trust in AI Outputs

Generative AI requires verification.

Problem 5 — Poor Communication

Strong analysis can fail if communicated badly.
