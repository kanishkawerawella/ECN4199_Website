Final Project

ECN 4199 — Final Group Project

Industrial Data Analytics Final Project

The Final Project is the capstone assessment component of:

ECN 4199 — Industrial Data Analytics

This project carries:

35 Marks

and is designed to integrate the computational, analytical, and interpretive skills developed throughout the semester.

Project Structure

This is a:

Group-Based Interdisciplinary Analytics Project

Each project group must consist of:

3–4 students

Importantly, each group MUST include students from BOTH:

  • Finance and Banking (F & B) Stream
  • Transport Economics and Commercial Shipping (TECS) Stream

The objective is to encourage interdisciplinary collaboration and exposure to different analytical and domain perspectives.

Students are encouraged to form balanced teams with complementary strengths in:

  • economics
  • analytics
  • interpretation
  • visualization
  • communication
  • coding

Purpose of the Project

This project integrates the full range of concepts covered throughout the semester.

Students are expected to:

  • formulate a meaningful analytical question
  • work with real-world data
  • clean and prepare datasets
  • perform computational analysis
  • generate visualizations and/or predictive systems
  • interpret findings critically
  • communicate insights professionally

The purpose is NOT merely to:

  • run code
  • generate graphs
  • maximize model accuracy

The purpose is to demonstrate the ability to:

think computationally about economic and business problems

Project Development Process

Students are strongly advised to approach the project systematically rather than immediately attempting to build complex models.

A strong analytics project typically progresses through the following stages.

Stage 1 — Topic Selection

Students should first identify:

  • an economic problem
  • business problem
  • policy issue
  • forecasting problem
  • behavioral pattern
  • or analytical question

that is both:

  • meaningful
  • realistically achievable within the semester

Students are encouraged to choose topics that genuinely interest them.

Stage 2 — Preliminary Data Exploration

Before finalizing the project, groups should:

  • identify possible datasets
  • inspect data quality
  • assess data availability
  • examine variable structure
  • evaluate feasibility

Projects with unrealistic data requirements are discouraged.

Stage 3 — Conceptual Note Submission

Before:

30.06.2026

each group must submit:

  • proposed project title
  • names and index numbers of all group members
  • one-page conceptual note

through the LMS under:

Final Project → Conceptual Note

The conceptual note should briefly explain:

  • proposed analytical question
  • motivation
  • proposed data source
  • possible analytical methods
  • expected contribution

LMS Submission Link

Submit Concept Note

Stage 4 — Feasibility Discussion with Lecturer

After submitting the conceptual note, each group must arrange a discussion with the lecturer regarding:

  • project feasibility
  • dataset suitability
  • analytical scope
  • technical complexity
  • realism of proposed methods

Important:

Contacting the lecturer and arranging the discussion is entirely the responsibility of the student group.

Failure to arrange this discussion may lead to poorly scoped or unrealistic projects.

Stage 5 — Project Development

Following approval and feedback, groups should proceed with:

  • data cleaning
  • exploratory analysis
  • visualization
  • modeling
  • interpretation
  • documentation
  • reproducibility checks

Students are strongly encouraged to develop the project incrementally throughout the semester rather than postponing all work until the final weeks.

Expected Project Components

Each final project should contain the following sections.

1. Project Title

The title should clearly reflect:

  • the analytical objective
  • the dataset/problem
  • the economic or business context

2. Introduction and Motivation

Students must clearly explain:

  • the analytical question
  • why the question matters
  • the economic/business relevance
  • the motivation behind the study
  • the objective of the project

Weak example:

Using AI on economic data.

Better example:

Can macroeconomic indicators help forecast inflation instability in Sri Lanka?

3. Dataset Description

Students must explain:

  • source of data
  • variables used
  • time period
  • unit of observation
  • limitations of the dataset

Examples of Data Sources

Source Examples
Central Bank of Sri Lanka Inflation, reserves, exchange rate
World Bank Development indicators
IMF Macroeconomic indicators
Kaggle Business datasets
Survey Data Household or labour datasets
News Data NLP projects

Students must properly acknowledge all datasets used.

4. Data Cleaning and Preprocessing

Students are expected to:

  • clean datasets
  • handle missing values
  • preprocess variables
  • document transformations

Examples include:

  • removing missing values
  • converting date formats
  • renaming variables
  • scaling variables
  • cleaning text data

Poor preprocessing leads to:

  • unreliable analysis
  • unstable models
  • misleading conclusions

5. Exploratory Data Analysis

Students must explore the data before modelling.

Expected components:

Task Example
Summary statistics Mean, median, variance
Visualization Line graphs, scatter plots
Pattern identification Trends, outliers
Correlation analysis Variable relationships

Students must interpret graphs and outputs economically.

Simply producing graphs without explanation is insufficient.

6. Modelling and Analytics

Students should apply appropriate analytical techniques.

Possible methods include:

Topic Example Methods
Regression Linear regression
Classification Logistic regression
Clustering K-Means
Forecasting ARIMA
NLP Sentiment analysis
Dashboarding Interactive visualization

Students must explain:

  • why a method was chosen
  • how the method works conceptually
  • limitations of the approach

Using very complex models without understanding them is discouraged.

A simple model with strong interpretation is better than:

complex code without understanding

7. Results and Interpretation

Students must explain:

  • major findings
  • patterns observed
  • predictive performance
  • economic/business meaning

Outputs alone are NOT analysis.

Interpretation is essential.

Weak interpretation:

Model accuracy = 92%.

Better interpretation:

The model predicts inflation reasonably well during stable periods, though performance weakens during crisis periods.

8. Critical Reflection and Limitations

Students must critically evaluate:

  • weaknesses of the model
  • limitations of the dataset
  • forecasting uncertainty
  • ethical concerns
  • assumptions made

Every project MUST contain a limitations section.

Examples include:

  • small sample size
  • missing data
  • model instability
  • overfitting
  • AI hallucinations
  • structural breaks

9. Ethical Reflection

Students should discuss ethical implications where relevant.

Area Ethical Concern
Classification Bias and exclusion
AI systems Hallucinations and misinformation
Forecasting False certainty
Dashboards Misleading communication

Analytics systems affect:

  • policy
  • firms
  • labour markets
  • households
  • public understanding

Ethical responsibility matters.

10. Reproducibility and Documentation

Projects should be reproducible.

Students are expected to:

  • organize files clearly
  • comment code properly
  • explain analytical steps
  • use readable variable names

Example:

# Load inflation dataset
inflation = pd.read_csv("inflation.csv")

Professional analytics requires:

  • transparency
  • documentation
  • reproducibility

Submission Requirements

Final project submissions must include ALL of the following components.

Item Required
Final Report (PDF) Yes
Python Notebook (.ipynb) Yes
Dataset(s) Used Yes
Visualizations Yes
AI Usage Declaration Yes

Final Report Requirements

The final written report must:

  • be professionally structured
  • clearly written
  • analytically rigorous
  • properly referenced

The report should be approximately:

4,000 words

excluding references and appendices.

Students are encouraged to use:

  • tables
  • visualizations
  • figures
  • workflow diagrams
  • model summaries

where appropriate.

Notebook Requirements

Students must:

  1. Organize notebooks clearly
  2. Comment code properly
  3. Use readable variable names
  4. Ensure code runs correctly
  5. Maintain reproducibility

Example:

# Load inflation dataset
inflation = pd.read_csv("inflation.csv")

Poorly documented notebooks will reduce marks.

Dataset Requirements

All datasets used in the project must also be submitted.

Datasets should be:

  • clearly labeled
  • organized properly
  • reproducible where possible

Students must acknowledge all data sources properly.

AI Usage Policy and Declaration

Students are permitted to use AI tools such as:

  • ChatGPT
  • GitHub Copilot
  • Gemini
  • Claude
  • other generative AI systems

for support purposes.

However:

  • AI-generated outputs must be critically verified
  • students remain fully responsible for all submitted work
  • blind copying of AI-generated code or interpretation is unacceptable

Importantly, all groups MUST explicitly acknowledge and document:

  • whether AI tools were used
  • which tools were used
  • how the tools were used

Examples include:

  • code assistance
  • debugging
  • visualization support
  • brainstorming
  • writing assistance

Students should include a brief:

AI Usage Declaration

section within the final report.

Failure to disclose substantial AI assistance may be treated as an academic integrity issue.

Suggested Project Areas

Students may choose projects from broad areas such as:

1. Macroeconomic Forecasting

Examples:

  • inflation forecasting
  • exchange rate forecasting
  • reserve adequacy analysis
  • GDP growth forecasting

2. Labour Market Analytics

Examples:

  • unemployment prediction
  • labour force participation analysis
  • gender wage gap analytics
  • education and employment outcomes

3. Business Analytics

Examples:

  • customer segmentation
  • demand forecasting
  • sales analytics dashboards
  • firm performance prediction

4. NLP and AI Projects

Examples:

  • sentiment analysis of economic news
  • AI-assisted policy analysis
  • economic narrative tracking
  • central bank speech analysis

5. Development and Policy Analytics

Examples:

  • poverty prediction
  • welfare targeting systems
  • household vulnerability analysis
  • district-level development dashboard

Important Recommendation

Choose a topic that:

  • genuinely interests your group
  • has available data
  • can be completed realistically within the semester
  • allows meaningful economic interpretation

Do not choose a topic only because it sounds technically advanced.

Common Mistakes to Avoid

Problem 1 — Overly Ambitious Projects

Do not attempt extremely large projects beyond the course scope.

Problem 2 — Blind Use of AI Tools

AI-generated code must be:

  • understood
  • verified
  • interpreted critically

Problem 3 — Weak Interpretation

Graphs and outputs without interpretation are insufficient.

Problem 4 — Poor Documentation

Unreadable notebooks reduce project quality.

Problem 5 — Ignoring Limitations

Every model and dataset has limitations.

Academic Integrity

Students may use:

  • lecture materials
  • documentation
  • AI tools for support

However:

  • plagiarism is not allowed
  • copied projects are not allowed
  • submitting code without understanding is unacceptable
  • AI-generated content must be critically verified

Students are responsible for all submitted work.
